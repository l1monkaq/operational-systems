## 1. Мета роботи
Дослідити принципи багатопотокового програмування за стандартом POSIX Threads (pthreads) у мові C. Опанувати системні виклики та бібліотечні функції `pthread_create`, `pthread_join`, передачу даних у потоки через універсальні вказівники `void*`, декомпозицію масивів на паралельні непересічні зрізи (Slices) та аналіз умов відсутності стану гонитви (Race Condition Freedom).

---

## 2. Теоретичні відомості

У середовищі Linux потік (Thread) — це полегшений процес (LWP, Light-Weight Process), що створюється за допомогою системного виклику `clone()` зі спільним адресним простором, дескрипторами файлів і таблицею сигналів, але з власним незалежним стеком та лічильником інструкцій (PC).

| Функція | Призначення |
|---|---|
| `pthread_create(&tid, attr, start_routine, arg)` | Створює новий потік, що починає виконання з функції `start_routine(arg)`. |
| `pthread_join(tid, &retval)` | Блокує поточний потік до завершення потоку `tid`, забираючи результат і звільняючи внутрішні ресурси потоку (аналог `waitpid`). |

## 3. Виконання завдань та аналіз результатів

### Завдання 1. Програма `threads_demo.c`
Компіляція з прапором `-pthread` та запуск:
```bash
gcc -Wall -Wextra -pedantic -pthread -o threads_demo threads_demo.c
./threads_demo
```
* **Отриманий результат:**
```
Потік 0: часткова сума = 55
Потік 2: часткова сума = 20055
Потік 1: часткова сума = 10055
Потік 3: часткова сума = 30055
Загальна сума: 60220
```
* **Аналіз формули:**
  Для кожного потоку $i$:
  $$\text{result}_i = \sum_{j=1}^{10} (j + i \times 1000) = \frac{1 + 10}{2} \times 10 + 10 \times 1000 \times i = 55 + 10000 \times i$$
  * $i=0: 55$
  * $i=1: 10055$
  * $i=2: 20055$
  * $i=3: 30055$
  * $\text{Total} = 55 + 10055 + 20055 + 30055 = 60220$.
* **Чому порядок рядків змінюється:** Потоки плануються ядром операційної системи повністю асинхронно і конкурентно (preemptive scheduling). Порядок отримання квантів процесорного часу ядрами залежить від поточного навантаження системи, кешу процесора та переривань, тому порядок виведення `printf` є недетермінованим.
* **Чому кожен потік має окремий `jobs[i]`:** Передача адреси локальної змінної лічильника циклу `&i` призвела б до стану гонитви (race condition), оскільки значення `i` змінювалося б швидше, ніж потік встиг його зчитати. Окремий елемент масиву `jobs[i]` гарантує ізольоване зберігання вхідних аргументів і результуючого значення.

### Завдання 2. Масштабування до 8 потоків
* **Параметри:** `NUM_THREADS = 8`, верхня межа циклу $N = 5$.
* **Розрахунок за формулою:**
  $$\text{result}_i = \sum_{j=1}^{5} (j + i \times 1000) = \frac{1 + 5}{2} \times 5 + 5 \times 1000 \times i = 15 + 5000 \times i$$

| Потік ($i$) | Розрахункова часткова сума |
|:---:|:---:|
| 0 | 15 |
| 1 | 5 015 |
| 2 | 10 015 |
| 3 | 15 015 |
| 4 | 20 015 |
| 5 | 25 015 |
| 6 | 30 015 |
| 7 | 35 015 |
| **Загальна сума** | **140 120** |

*Перевірка:* $15 \times 8 + 5000 \times \frac{0 + 7}{2} \times 8 = 120 + 5000 \times 28 = 120 + 140000 = 140120$. Експериментальний запуск програми підтвердив точний збіг із теоретичним прогнозом.

### Завдання 3. Паралельне сумування масиву `sum_array.c`
Компіляція та запуск:
```bash
gcc -Wall -Wextra -pedantic -pthread -o sum_array sum_array.c
./sum_array
```
* **Результат:**
```
Сума 1..100 = 5050
```
* **Теоретична формула Арифметичної прогресії (Гаусс):**
  $$S = \frac{1 + 100}{2} \times 100 = 5050$$
* **Чому тут немає стану гонитви (Data Race Freedom):**
  1. Масив `data` після ініціалізації використовується потоками **виключно в режимі читання** (Read-Only). Одночасне читання пам'яті кількома ядрами процесора є абсолютно безпечним.
  2. Запис проміжного результату виконується кожним потоком у власну незалежну комірку пам'яті: `slices[t].sum`.
  3. Фінальна сума `total` обчислюється головним потоком послідовно **після** виклику `pthread_join`, що встановлює строгий бар'єр синхронізації «happens-before».

## 4. Відповіді на питання для захисту

1. **Які аргументи отримує `pthread_create` і для чого потрібен четвертий параметр?**
   `pthread_create(pthread_t *thread, const pthread_attr_t *attr, void *(*start_routine)(void *), void *arg)`:
   * 1-й: вказівник на змінну для запису ID нового потоку;
   * 2-й: атрибути потоку (пріоритет, розмір стека; `NULL` — за замовчуванням);
   * 3-й: вказівник на функцію потоку;
   * 4-й (`arg`): вказівник типу `void*` на вхідні дані, що передаються у функцію потоку. Він дозволяє передати в потік будь-яку структуру, число або масив параметрів.

2. **Що робить `pthread_join`?**
   `pthread_join` призупиняє виконання викликаючого потоку доти, доки зазначений цільовий потік не завершиться. Крім того, він забирає значення, повернуте потоком через `return` або `pthread_exit`, і автоматично звільняє ресурси дескриптора потоку (запобігаючи аналогу «зомбі» серед потоків).

3. **Чому для компіляції потокових програм потрібен прапор `-pthread`?**
   Прапор `-pthread` для компілятора GCC:
   * Підключає системну бібліотеку потоків POSIX (`libpthread`);
   * Визначає препроцесорні макроси (наприклад, `_REENTRANT`), які активують потокобезпечні (thread-safe) версії функцій стандартної бібліотеки C;
   * Налаштовує параметри лінкера для коректної підтримки Thread Local Storage (TLS).

4. **Чому порядок завершення потоків не гарантований?**
   Операційна система Linux використовує витискальне планування (Preemptive CFS / EEVDF). Планувальник ядер розподіляє кванти часу на основі динамічних пріоритетів, апаратних переривань, міграції між ядрами процесора та затримок звернення до пам'яті (NUMA). Жоден потік не має гарантій швидкості виконання відносно інших.

5. **У чому різниця між потоком і процесом у Linux?**
   * **Процес** володіє власним ізольованим адресним простором, своєю таблицею дескрипторів та змінними середовища. Перемикання контексту між процесами є «важким» через необхідність скидання кешу сторінкової пам'яті (TLB).
   * **Потік** існує всередині процесу і ділить з іншими потоками того самого процесу єдиний спільний адресний простір (купу, глобальні змінні, дескриптори файлів). Потоки мають лише власний стек, регістри та лічильник інструкцій, завдяки чому обмін даними між ними відбувається напряму через пам'ять.
