# Лабораторна робота №2. Системні виклики ядра Linux для роботи з файловими дескрипторами

**Предмет:** Операційні системи  | **Група:** ІПЗ-41  | **Виконала:** Єва Якимчук

---

## 1. Мета роботи
Дослідити низькорівневий інтерфейс системних викликів ядра Linux (POSIX/UNIX syscalls) для введення-виведення: `open`, `read`, `write`, `lseek`, `close`. Навчитися працювати з цілочисельними файловими дескрипторами, правильно обробляти помилки часу виконання за допомогою глобальної змінної `errno` та функції `strerror`, а також реалізувати утиліту буферизованого копіювання файлів.

---

## 2. Теоретичні відомості про системні виклики

| Системний виклик | Сигнатура | Призначення | Повертає в разі успіху | Повертає в разі помилки |
|---|---|---|---|---|
| **`open`** | `int open(const char *pathname, int flags, mode_t mode)` | Відкриває або створює файл, створюючи запис у відкритій файловій таблиці ядра. | Невід'ємний цілий дескриптор $\ge 0$ | `-1` (встановлює `errno`) |
| **`write`** | `ssize_t write(int fd, const void *buf, size_t count)` | Записує до `count` байтів із буфера пам'яті за дескриптором `fd`. | Кількість фактично записаних байтів | `-1` |
| **`read`** | `ssize_t read(int fd, void *buf, size_t count)` | Зчитує до `count` байтів із файлу в буфер пам'яті. | Кількість прочитаних байтів (`0` — EOF) | `-1` |
| **`lseek`** | `off_t lseek(int fd, off_t offset, int whence)` | Змінює поточне зміщення (file offset) для дескриптора `fd`. | Нове результуюче зміщення від початку | `-1` |
| **`close`** | `int close(int fd)` | Звільняє дескриптор і зменшує лічильник посилань на відкритий файл у ядрі. | `0` | `-1` |

Прапорці:
* `O_WRONLY`: відкриття лише на запис.
* `O_CREAT`: створення файлу, якщо він не існує (вимагає третього аргументу `mode`, наприклад `0644`).
* `O_TRUNC`: якщо файл існував, його розмір скидається до нуля (очищення вмісту).

## 3. Виконання завдань та аналіз результатів

### Завдання 1. Програма `fd_demo.c`
Компіляція із суворими прапорами:
```bash
gcc -Wall -Wextra -pedantic -o fd_demo fd_demo.c
./fd_demo
```
* **Фактичний вивід програми:**
```
Прочитано 18 байтів: Hello from lab-02
Зі зміщення 11 прочитано 6 байтів: lab-02
```
* **Пояснення:** Рядок `"Hello from lab-02\n"` має довжину 18 байтів (індекси 0..17). Зсув `lseek(fd, 11, SEEK_SET)` переміщує курсор читання безпосередньо на символ `'l'` слова `'lab-02'`. Подальше зчитування 6 байтів повертає рядок `"lab-02"`.

### Завдання 2. Прогнозування при зміні зміщення
* **Експеримент:** `lseek(fd, 0, SEEK_SET)` та читання 5 байтів.
* **Прогноз:** Оскільки зміщення дорівнює `0` (початок файлу), зчитування перших 5 символів має повернути підрядок `"Hello"`.
* **Результат експерименту:**
```
Зі зміщення 0 прочитано 5 байтів: Hello
```
Прогноз повністю збігся з результатом.

* **Трасування через `strace`:**
```bash
strace -e trace=openat,read,write,lseek,close ./fd_demo
```
У журналі трасування зафіксовано точні переходи в простір ядра (Kernel Space):
1. `openat(AT_FDCWD, "notes.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644) = 3`
2. `write(3, "Hello from lab-02\n", 18) = 18`
3. `close(3) = 0`
4. `openat(AT_FDCWD, "notes.txt", O_RDONLY) = 3`
5. `read(3, "Hello from lab-02\n", 63) = 18`
6. `lseek(3, 11, SEEK_SET) = 11`
7. `read(3, "lab-02", 6) = 6`
8. `close(3) = 0`

### Завдання 3. Міні-копіювач файлів `copy_file.c`
Компіляція та перевірка побайтового збігу:
```bash
gcc -Wall -Wextra -pedantic -o copy_file copy_file.c
./copy_file notes.txt notes-copy.txt
cmp notes.txt notes-copy.txt
```
* Команда `cmp` завершилася без виводу (код завершення `0`), що підтверджує 100% ідентичність файлів `notes.txt` та `notes-copy.txt`.
* **Чому записують рівно `n` байтів:**
  Виклик `read(in, buf, sizeof(buf))` повертає $n$ — фактичну кількість прочитаних байтів (яка для останнього блока файлу або невеликого файлу завжди менша за 4096). Якщо передати у `write` розмір `sizeof(buf)`, у вихідний файл запишеться невизначене «сміття» з неініціалізованої пам'яті залишку буфера.

## 4. Відповіді на питання для захисту

1. **Що таке файловий дескриптор і що повертає `open` у разі помилки?**
   Файловий дескриптор (File Descriptor, FD) — це невід'ємне ціле число (індекс у таблиці відкритих файлів процесу в структурі ядра `task_struct`), яке однозначно ідентифікує відкритий файл або ресурс вводу-виводу (сокет, пайп). У разі помилки `open` повертає значення `-1` і записує числовий код помилки в глобальну змінну `errno`.

2. **Для чого потрібні прапорці `O_CREAT` і `O_TRUNC`?**
   * `O_CREAT` інструктує ядро створити файл, якщо він ще не існує (вимагає передачі бітової маски прав `mode`, наприклад `0644` — читання/запис для власника, читання для інших).
   * `O_TRUNC` (truncate) обнуляє довжину вже наявного файлу до 0 байтів у момент відкриття, перезаписуючи його старий вміст.

3. **Що змінює виклик `lseek`?**
   `lseek` змінює поточну позицію вказівника файлового зміщення (file offset) у структурі відкритого файлового опису (file description) ядра. Він не звертається до диску та не змінює вміст файлу, а лише визначає, з якої позиції почнеться наступна операція `read` або `write`.

4. **Чому у `copy_file` записують рівно `n` байтів, а не `4096`?**
   Тому що розмір файлу рідко є кратним 4096 байтам. В останній ітерації циклу `read` повертає залишок байтів ($n < 4096$). Запис повного буфера призведе до пошкодження файлу-призначення через дописування зайвих байтів зі старого вмісту буфера пам'яті.

5. **Чи можна виконати ці операції без системних викликів, лише функціями бібліотеки?**
   Ні. Хоча функції стандартної бібліотеки мови C (`fopen`, `fread`, `fwrite`, `fclose`, `fseek`) надають зручніший високорівневий буферизований інтерфейс зі структурою `FILE*`, під капотом вони обов'язково викликають ті самі фундаментальні системні виклики ядра (`open`, `read`, `write`, `close`), оскільки лише ядро операційної системи має привілейований доступ до фізичних накопичувачів і файлових систем.
